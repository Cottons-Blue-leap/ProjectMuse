# 06 · 채널 홈·재생목록·종료화면 — 따뜻한 표면 심화

> R&D 자료 · **결단 자리 X**. 토대 = [01 진단](01_channel_diagnostic.md) 발견2 + [리서치 A·B](_data/market_research_2026-06.md).
> s402 (2026-06-06).

> **⚠️ 코튼 피드백 교정 (s402, 2026-06-06).** 아래 §0·§2가 **매그니튜드를 과장**했었다. 정정:
> 1. **재생목록은 "최강 즉시 레버 ★"가 아니다.** 트래픽 = 534뷰의 4.9% ≈ 26뷰. *뷰당 체류가 길다*를 *레버가 크다*로 바꿔치기한 오류. 26뷰 표면 = 레버 아닌 (잘해야) 복리 인프라이고, 8영상에선 복리도 ≈0. → 등급 강등: "즉시 레버"가 아니라 *저비용·저우선 인프라*.
> 2. **"재생목록 첫 곡 = 고유지율곡 정렬"은 측정 불가.** 곡별 N 수십에서 녹턴 47.78% vs 조플린 40.85%는 노이즈 안쪽 → 신뢰성 있는 유지율 랭킹 불가. 판단 가능한 사전값은 *인지도*뿐. → **정렬 기준 = 유지율(X) → 인지도(O)**, 유지율은 N 쌓이면 *검증*할 값으로 미룸.
> 3. **마스터 재생목록 신축 = 지금 보류.** 8영상에선 시대 재생목록이 이미 auto-chain → 마스터는 중복. ~15-20영상에서 재고.
> 본문은 원 추론 트레일 보존용으로 남기되, 위 교정이 우선한다.

## 0. 한 줄

**재생목록(141초)·종료화면(290초)은 채널에서 가장 깊은 시청자인데 트래픽의 5%·0.4%로 과소활용된다.** 이 따뜻한 표면을 체이닝하면 *세션 시청시간*(2025 알고리즘 핵심 신호)이 곧장 오른다. 통제 가능 + 변환 최고 + 저비용. (단 ⚠️교정: *현재 볼륨이 작아* 레버 크기는 작다 — 복리 인프라로 봐야.)

## 2. 재생목록 (최강 저비용 레버)

리서치 A·B: 재생목록 = 자동연속재생 + 세션시간 배가 + *검색 indexable*. 우리 시대 재생목록(5시대) + 로케일별 desc 이미 운영 → 보강안:
- ~~**마스터 재생목록 신축**~~ → **지금 보류** (⚠️교정): 8영상에선 시대 재생목록이 이미 auto-chain하므로 마스터는 중복. 카탈로그 ~15-20영상 시 재고. 그때 = "All · Atelier Miku Acappella" 시간순.
- **재생목록 정돈**: 각 시대 재생목록 첫 곡 = *가장 **인지도** 높은 곡* (⚠️교정: "유지율"은 현 N에서 측정 불가 → *인지도 사전값*으로 정렬, 유지율은 후일 검증값). 클릭 후 첫인상 = 이탈 방지. 예 낭만 첫 곡 = 녹턴(고인지도).
- 무드/테마 재생목록 실험(별도): "Calm Piano, A Cappella" 등 — ④의 relaxation 프레이밍을 *제목 아닌 재생목록*에서 안전하게 테스트하는 자리.
- 곡 사이 *내러티브*(curator voice desc) = 시리즈 정체성 강화.

## 3. 종료화면 (체류 290초 = 미정착)

리서치 B: 종료화면 = 세션 시청시간(상위 신호). 표준화:
- **전 영상 종료화면 2~3요소 표준**: ①다음 곡(같은 시대 또는 가장 인지도 높은 미시청 곡) ②시대 재생목록 ③구독.
- 곡간 연결 논리 = *유지율 높은 곡으로 보내기*(녹턴·조플린·비발디) → 세션 연장.
- video_release workflow에 "종료화면 표준" 체크 추가 검토(현재 곡별 수동이면 누락 위험 = error_journal 류).

## 4. 채널 홈 레이아웃

리서치 A·B: 채널 페이지(트래픽 5.3%·체류 31초 = 짧음 → 첫인상 약할 수 있음). 보강:
- **채널 트레일러**(비구독자용) = 시리즈 본질 30~60초("악기 없이, 전곡을, N명의 미쿠가" 시그너처 훅 + 명화 몽타주). 신규 방문자 전환.
- **섹션 큐레이션**: 상단 = "시작하기 좋은 곡"(인지도+유지율 높은 3곡) → 시대별 재생목록 행 → 최신.
- 채널 설명·키워드 = 보컬로이드 클러스터 + a cappella + classical(④ 정합).

## 5. Premieres (engagement 스파이크)

리서치 A: 예약 자동공개 → **Premiere 전환** 시 라이브챗·카운트다운 engagement 스파이크 = 발행 직후 알고리즘 부스트. 우리 이미 예약공개 운영 → *Premiere 토글*만으로 적용 가능. 단 1인이라 라이브챗 응대 부담 = 곡별 선택.

## 8. 실행 묶음 (비용·리스크 낮은 순)
